## 3. Native Capabilities & Open-Source Alternatives Analysis

### A. OpenCode Native Capabilities
* **Native Slash Commands (`.opencode/commands/`):** OpenCode automatically registers Markdown prompt commands stored in `.opencode/commands/`.
  * **Selected Solution:** Implement `.opencode/commands/memory-status.md` and `.opencode/commands/handoff.md`.
  * **Benefit:** Zero dependencies, zero binary modifications, native CLI/IDE user accessibility.

### B. Open Source Architectural Standards
* **ADR (Architecture Decision Records) - MADR / Nygard Format:**
  * **Selected Solution:** Standardized Markdown ADR schema in `.openmemory/adrs/ADR-xxx.md`.
  * **Data Structure:** `ADRRecord { id, title, status, date, context, decision, consequences }`.
  * **Benefit:** Universal format readable by both human developers and LLM agents.

### C. Rejected Alternatives
* **Vector DBs (ChromaDB, Pinecone, LanceDB) / AGPL Frameworks (Claude-Mem):**
  * **Reason for Rejection:** Re-introduces heavy native C++ dependencies or AGPL licensing risks. OpenMemory's mandate is zero-dependency, Clean-room MIT native TypeScript.

## 4. Sub-phase F3.4 Technical Contract & Ambiguity Resolution

The F3.4 technical contract has been reviewed and closed with zero ambiguity:

### Contract Specifications:

1. **`ADRRecord` Data Model & StorageEngine Methods:**
   * Schema:
     ```typescript
     export interface ADRRecord {
       id: string; // e.g. "ADR-001"
       title: string;
       status: "PROPOSED" | "ACCEPTED" | "REJECTED" | "SUPERSEDE" | "DEPRECATED";
       date: string; // YYYY-MM-DD or ISO
       context: string;
       decision: string;
       consequences?: string;
     }
     ```
   * StorageEngine Methods:
     * `saveADR(adr: Omit<ADRRecord, "id"> & { id?: string }): ADRRecord`: Saves `ADR-xxx.md` atomically using `atomicWriteFileSync`.
     * `listADRs(): ADRRecord[]`: Reads `.openmemory/adrs/`, parses frontmatter/markdown headers, and returns sorted list.
     * `getADR(id: string): ADRRecord | null`: Retrieves single ADR content.

2. **Task State & Goal Mutation Methods (`src/storage.ts`):**
   * `addTask(description: string, status?: TaskStatus): TaskState`
   * `updateTaskStatus(id: string, status: TaskStatus): TaskState`
   * `setActiveGoal(goal: string, phase?: string): ProjectState`

3. **Project Context Synthesis (`formatProjectContextSummary()`):**
   * Generates a concise Markdown summary combining project metadata, active phase & goal, task status, ADR registry index, and handoff continuity pointers.

4. **Native OpenCode Slash Commands (`.opencode/commands/`):**
   * `.opencode/commands/memory-status.md`: Prompts agent to query project state, ADRs, and memory summary.
   * `.opencode/commands/handoff.md`: Prompts agent to present active session handoff summary.

5. **Plugin Lifecycle Integration (`.opencode/plugins/openmemory.ts`):**
   * Emits project context summary during `session.created`.
   * Preserves backward compatibility with F3.1–F3.3 hooks.
