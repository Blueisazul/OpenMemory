## 1. Definición del Problema Real

### OpenCode Responsibilities (Execution / Runtime Boundary):
- Execution of agents & subagents (`Scout`, `Explore`, etc.).
- Execution of tools (`WebSearch`, `WebFetch`, `file_view`, `bash`).
- Execution of Skills defined in `.opencode/skills/`.
- LLM reasoning, research, and finding synthesis.

### OpenMemory Responsibilities (Memory / Knowledge / Continuity Boundary):
- Local-first, zero-dependency persistence under `.openmemory/`.
- Cross-session state continuity & handoff (`handoff.md`, `project-state.json`).
- Architectural Decision Records (`ADRRecord` in MADR format).
- Research provenance and knowledge persistence (`ResearchRecord`, `Sources`, `Repositories`, `Findings`).
- Atomic disk writes, diagnostic self-healing, and STDIO MCP Server adapter.

## 2. Inventario de Alternativas Open Source Investigadas

Se realizó una auditoría exhaustiva de soluciones existentes en el ecosistema OpenCode y frameworks de memoria para IA:

### Categoría A: Plugins de Memoria Específicos para OpenCode
1. **`ZeR020/opencode-mem0` & `andy-zhangtao/opencode-mem`:**
   - *Licencia:* MIT (adaptador wrapper).
   - *Arquitectura:* Envoltorio sobre la librería `mem0ai/mem0`.
   - *Almacenamiento/Dependencias:* Requiere claves API externas (OpenAI Embeddings / Pinecone) o una base de datos vectorial local (Qdrant/Chroma).
   - *Fricción OS/Windows:* Alta fricción al requerir contenedores Docker o binarios nativos para vector DBs.
   - *Filtro de Conocimiento:* Solo persiste fragmentos de conversación e impresiones del usuario, no hallazgos técnicos estructurados ni ADRs.

2. **`cioffiAI/opencode-memory` & `ezzddinne/opencode-memory`:**
   - *Licencia:* MIT.
   - *Arquitectura:* Escritura simple append-only de transcripciones de chat a archivos Markdown locales.
   - *Almacenamiento/Dependencias:* Cero dependencias externas, pero carece de escrituras atómicas, validación de esquemas, autosanado o búsquedas estructuradas.
   - *Filtro de Conocimiento:* Ruidoso; vuelca conversaciones completas en lugar de conocimiento sintético.

3. **`chncaesar/opencode-plugin-memory` & `tickernelz/opencode-mem`:**
   - *Licencia:* MIT.
   - *Arquitectura:* Integración con `sqlite3` o `node-sqlite3` para persistencia relacional.
   - *Dependencias:* Módulos binarios C++ nativos (`node-gyp`).
   - *Fricción OS/Windows:* Falla frecuentemente en entornos Windows sin herramientas de compilación C++ (MSVC) instaladas, violando la premisa de `zero-dependency`.

4. **`EchoesVault` / `opencode-openmemory`:**
   - *Licencia:* MIT.
   - *Arquitectura:* Sincronizador de bóvedas Markdown (estilo Obsidian) para notas personales.
   - *Filtro de Conocimiento:* Enfocado en notas de usuario, no en continuidad operativa de agentes ni trazabilidad de fuentes.

### Categoría B: Frameworks Generales de Memoria para IA (Mem0, Letta, Cognee)
1. **`mem0ai/mem0` (Python/JS SDK):**
   - *Licencia:* Apache-2.0.
   - *Arquitectura:* Grafo/Vector híbrido para memoria de preferencias de usuario.
   - *Incompatibilidad:* Requiere servicios externos SaaS o Vector DBs locales pesados. No es una solución TypeScript nativa zero-dependency.

2. **`Letta` (anteriormente MemGPT):**
   - *Licencia:* Apache-2.0.
   - *Arquitectura:* Servidor de memoria con bloques de memoria de trabajo/persona.
   - *Incompatibilidad:* Servidor externo escrito en Python con dependencias de PostgreSQL y Pgvector.

3. **`Cognee`:**
   - *Licencia:* Apache-2.0.
   - *Arquitectura:* Grafo de conocimiento sobre Neo4j / NetworkX.
   - *Incompatibilidad:* Servidor de base de datos de grafos externo.

## 4. Distinción: Memoria Conversacional vs. Research Engine

La auditoría confirma una diferencia conceptual crítica:

- **Memoria Conversacional (Lo que ofrecen plugins existentes):** Almacena "¿Qué dijo el usuario en el turno 3?" o "Al usuario le gusta TypeScript". *Genera un ruido inmenso y no resuelve el seguimiento de decisiones.*
- **Research Engine (Lo que necesita OpenMemory):** Almacena "¿Qué fuentes/repositorios se investigaron?", "¿Qué versión/commit de librería se evaluó?", "¿Qué hallazgos técnicos se descubrieron?" y "¿Qué ADR justifica la decisión tomada?".

Ninguno de los proyectos de la competencia ofrece un **Research Engine de Trazabilidad Técnica sin dependencias externas**.

## 5. Auditoría de Reutilización por Niveles

- **Nivel 1 — Conceptos:** **REUTILIZAR.** Conceptos comprobados de etiquetado de metadatos, procedencia de enlaces y políticas de ruido de memoria (Memory Noise Policy).
- **Nivel 2 — Formato:** **REUTILIZAR.** Alineación con el estándar MADR para ADRs y esquemas MCP unificados.
- **Nivel 3 — Código Directo:** **RECHAZAR.** El código existente en repositorios externos incluye dependencias de `sqlite3`, `mem0ai` o llamadas HTTP a OpenAI que violan el principio `zero-dependency`.
- **Nivel 4 — Plugin como Dependencia:** **RECHAZAR.** Convertir OpenMemory en un wrapper de `mem0` o `sqlite` introduciría fallos de compilación C++ en Windows y costos de licencias/API keys externas.
- **Nivel 5 — Sistema Completo:** **RECHAZAR.** No existe ningún backend externo que cumpla con ser local-first, zero-dependency, Clean-Room MIT y compatible con TypeScript nativo.

## 7. Dictamen Final y Recomendación Arquitectónica

### CONCLUSIÓN: `F5 DECISION: ADAPT / BUILD (HYBRID)`

- **ADAPT (Reutilizar Conceptos y Estándares):** Reutilizar los patrones conceptuales de procedencia de datos, descarte de ruido y esquemas de consulta léxica probados en la industria.
- **BUILD (Desarrollar Componente Mínimo Propio):** Extender `StorageEngine` en TypeScript nativo para soportar `.openmemory/knowledge/researches/` con escrito atómico (`atomicWriteFileSync`) y registrar las 2 herramientas MCP unificadas (`openmemory_record_knowledge` y `openmemory_query_knowledge`).

### Componentes que Permanecen Intactos:
- `StorageEngine` actual (persistencia de estado, handoffs, ADRs, backups, diagnósticos).
- Plugin oficial de OpenCode (`.opencode/plugins/openmemory.ts`).
- Servidor MCP nativo (`src/mcp.ts`).
- Instalador No Destructivo (`src/installer.ts`).
- Paquete de producción `npm` y CLI (`dist/`, `openmemory`).

### Componentes a Construir en la Fase 5:
- Entidades `ResearchRecord` y `KnowledgeItem` en `src/storage.ts`.
- Métodos `saveResearch()`, `getResearch()`, `listResearches()` y `queryKnowledge()` en `StorageEngine`.
- MCP Tools `openmemory_record_knowledge` y `openmemory_query_knowledge` en `src/mcp.ts`.
