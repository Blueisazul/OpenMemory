## 1. Executive Summary

- `[EVIDENCE]` Inspection of `@opencode-ai/plugin` SDK (`node_modules/@opencode-ai/plugin/dist/index.d.ts`) confirms that OpenCode provides native observability hooks (`"tool.execute.after"`, `"experimental.chat.system.transform"`, `"experimental.session.compacting"`, `"permission.ask"`, and `event`).
- `[CONCLUSION]` **OpenMemory DOES NOT need to build custom web search, scrapers, scout tools, or agent runtimes.** OpenCode already executes all of these native tools and exposes execution inputs/outputs directly to OpenCode plugins via `"tool.execute.after"`.
- `[DECISION]` **Hybrid Knowledge Capture Architecture (SELECTED):**
  - **Explicit Synthesis:** Agents use `openmemory_record_knowledge` when synthesizing structured findings (high signal-to-noise ratio).
  - **Automatic Observability:** The OpenMemory OpenCode plugin listens to `"tool.execute.after"` to automatically record lightweight provenance (source URLs, repo URLs, timestamps) without storing raw HTML/CLI dumps.
- `[CONCLUSION]` Re-verification of open-source projects (`Mem0`, `Letta`, `opencode-memory`, `opencode-mem0`, `sqlite3` adapters) confirms that direct dependency integration is **REJECTED** due to SaaS API key requirements, C++ native build breaks on Windows OS (`node-gyp`), and lack of structured research schemas.
- `[DECISION]` **F5.2 Implementation Path:** Proceed with native TypeScript extension of `StorageEngine` in `.openmemory/knowledge/researches/` and the 2 unified MCP tools (`openmemory_record_knowledge`, `openmemory_query_knowledge`).

## 3. Session & Context Lifecycle

- `[EVIDENCE]` OpenCode sessions manage chat history in volatile memory. During compaction (`session.compacted`), raw message turns are truncated.
- `[EVIDENCE]` `@opencode-ai/plugin` provides `experimental.session.compacting`, which allows OpenMemory to inject the `handoff.md` summary before context is wiped:
  ```typescript
  "experimental.session.compacting": async (input, output) => {
    output.context.push(storage.getOrInitHandoff());
  }
  ```
- `[CONCLUSION]` This mechanism guarantees zero data loss during context compaction without altering OpenCode's internal compaction logic.

## 4. Tool Execution Observability

- `[EVIDENCE]` Inspection of `@opencode-ai/plugin/dist/index.d.ts` (Lines 249–258) reveals:
  ```typescript
  "tool.execute.after"?: (input: {
      tool: string;
      sessionID: string;
      callID: string;
      args: any;
  }, output: {
      title: string;
      output: string;
      metadata: any;
  ```

- `[OBSERVATION]` When OpenCode executes `web_search`, `web_fetch`, `scout`, `explore`, or `bash`, OpenMemory receives `input.tool`, `input.args`, and `output.output`.
- `[DECISION]` OpenMemory will use `"tool.execute.after"` to automatically capture provenance metadata (URLs, repo names, tool names) while filtering out raw HTML/CLI dumps to prevent memory bloat.

## 10. Automatic vs. Explicit Capture

- **Option A (100% Automatic):** Parse all tool outputs. *(Rejected: Captures 90%+ noise, HTTP headers, raw HTML).*
- **Option B (100% Explicit):** Rely solely on agent memory. *(Rejected: Agent might forget to call MCP tool).*
- **Option C (Hybrid Architecture - SELECTED):**
  1. **Primary (Explicit):** Agent calls `openmemory_record_knowledge` when synthesizing research.
  2. **Secondary (Automatic):** Plugin listens to `"tool.execute.after"` to automatically record source URLs & repo metadata into lightweight provenance index.
  3. **Guidance:** SOP Skills in `.opencode/skills/` and `AGENTS.md` instruct developer agents to invoke `openmemory_record_knowledge` upon completing major research tasks.

## 11. Current F5 Data Model Review (Minimum Viable Scope)

The minimum data model consists of two cohesive entities:
1. `ResearchRecord` (`.openmemory/knowledge/researches/RES-xxx.json`): Topic, category, summary, status, related ADR ID, provenance.
2. `KnowledgeItem`: Type (`SOURCE` | `REPOSITORY` | `FINDING`), classification (`FACT` | `OBSERVATION` | `FINDING` | `HYPOTHESIS` | `CONCLUSION`), detail, evidence snippet, provenance metadata.

## 15. Recommended Integration Flow

```text
1. OpenCode Agent runs WebSearch / Scout / Explore.
2. OpenCode Plugin observes tool execution via "tool.execute.after" (logs provenance URL/repo).
3. Agent synthesizes findings and calls openmemory_record_knowledge.
4. StorageEngine validates payload via Memory Noise Policy and writes RES-xxx.json atomically.
5. In future sessions, experimental.chat.system.transform injects context summary into system prompt.
6. If agent queries specific past research, openmemory_query_knowledge performs fast lexical search (< 5ms).
```

## 16. Risks & Mitigation Strategies

| Risk Factor | Impact | Mitigation Strategy |
|---|---|---|
| **Agent forgets to record research** | Medium | SOP Skills (`.opencode/skills/`) and `AGENTS.md` prompt guidance instruct agent; `"tool.execute.after"` logs fallback provenance. |
| **Noise bloat in storage** | Medium | Memory Noise Policy limits payload to 10KB, max 10 findings per topic, strips raw HTML/diffs. |
| **Windows EPERM file locks** | Low | Atomic writer with 5-attempt retry loop in `StorageEngine.atomicWriteFileSync`. |

## 17. Answers to the 10 Authorization Questions (Section 16 Criteria)

1. **What OpenCode mechanism produces knowledge?** `WebSearch`, `WebFetch`, `Scout`, `Explore`, agent reasoning.
2. **What mechanism captures it?** Hybrid: `openmemory_record_knowledge` MCP tool + `"tool.execute.after"` plugin hook.
3. **Who decides what to persist?** Agent synthesizes; OpenMemory validates via Memory Noise Policy and persists.
4. **How to avoid losing it during compaction?** `experimental.session.compacting` hook injects handoff summary before compaction.
5. **How is it retrieved later?** `experimental.chat.system.transform` (auto-summary in system prompt) + `openmemory_query_knowledge` (lexical search).
6. **What part does OpenMemory do?** Persistence, provenance indexing, ADR linking, noise validation, MCP server, atomic storage.
7. **What part does OpenCode do?** All executions (agents, subagents, tools, search, skills runtime).
8. **Is there a reusable OSS solution?** Evaluated and rejected as code dependency; concepts adapted.
9. **What is the minimum persistence model?** `ResearchRecord` + `KnowledgeItem` JSON files under `.openmemory/knowledge/researches/`.
10. **What is the minimum new code required?** ~120 lines in `storage.ts` + ~60 lines in `mcp.ts`. Zero new dependencies.
