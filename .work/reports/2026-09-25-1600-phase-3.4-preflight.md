## A. Objetivo de F3.4

### Problema a resolver
Mientras F3.1–F3.3 garantizan la persistencia atómica en disco y el traspaso narrativo entre sesiones (`handoff.md`), OpenMemory aún carece de un **Motor Integrado de Contexto de Proyecto y Memoria Estructurada** que:
1. Gestione e indexe los Registros de Decisiones de Arquitectura (`.openmemory/adrs/ADR-xxx.md`).
2. Exponga métodos en `StorageEngine` para mutar tareas activas, cambiar metas de proyecto y consultar el índice de decisiones.
3. Proporcione comandos slash nativos de OpenCode (`/memory-status` y `/handoff`) bajo `.opencode/commands/` para permitir que usuarios y agentes consulten el estado de la memoria y la continuidad del proyecto bajo demanda.
4. Sintetice un resumen de contexto de proyecto unificado en `session.created`.

### Definición en OpenMemory
"Project Context & Memory Integration" significa conectar todos los artefactos persistentes (`project-state.json`, `openmemory.json`, `handoff.md`, `adrs/`) en una API coherente en `StorageEngine` y exponerla nativamente mediante comandos slash de OpenCode, sin requerir bases de datos vectoriales, embeddings o daemons externos.

### Alcance
- **DENTRO del alcance (IN Scope):**
  - Métodos ADR en `StorageEngine`: `saveADR()`, `listADRs()`, `getADR()`.
  - Métodos de Tareas/Metas en `StorageEngine`: `addTask()`, `updateTaskStatus()`, `setActiveGoal()`, `formatProjectContextSummary()`.
  - Comandos slash nativos de OpenCode en `.opencode/commands/memory-status.md` y `.opencode/commands/handoff.md`.
  - Suite de pruebas empíricas F3.4 (`.work/experiments/run-f34-context-tests.ts`).
- **FUERA del alcance (OUT of Scope):**
  - Vector DBs, embeddings, RAG, Knowledge Graphs.
  - Daemons externos, servidores HTTP/gRPC secundarios.
  - Modificación del binario/core de OpenCode.
  - Código AGPL-3.0 (e.g. `claude-mem`).

## B. Estado Existente y Gap Funcional

### Capacidades actuales (F3.1–F3.3)
- Persistencia atómica via `.tmp` y `fs.renameSync`.
- Manejo de lifecycle events (`session.created`, `session.idle`, `session.compacted`).
- Handoff estructurado en `handoff.md` respetando secciones de propiedad manual (`## Key Architectural Decisions`, `## Developer Notes`).
- Puntero delimitado en `AGENTS.md`.

### Gap Funcional Concreto de F3.4
1. **Falta de API de ADRs:** `.openmemory/adrs/` existe como directorio pero `StorageEngine` no tiene métodos para crear, indexar o leer ADRs.
2. **Falta de API de Mutación de Tareas/Metas:** No hay métodos programáticos para actualizar tareas o metas activas en `project-state.json`.
3. **Falta de Comandos Slash Nativos:** No existen definiciones bajo `.opencode/commands/` para invocación de `/memory-status` o `/handoff`.
4. **Falta de Resumen Sintetizado de Contexto:** `session.created` registra el recuento de palabras del handoff pero no un índice consolidado de fase, metas, tareas y ADRs.

## C. Investigación de Alternativas Open Source y Capacidades Nativas

### 1. Comandos Slash Nativos de OpenCode (`.opencode/commands/`)
- **Fuente/Licencia:** Documentación Oficial de OpenCode / Apache 2.0.
- **Maturidad:** Estándar nativo de OpenCode.
- **Qué resuelve:** OpenCode descubre automáticamente comandos definidos en `.opencode/commands/<nombre>.md` o `.opencode/commands/<nombre>.ts`.
- **Integración:** Complejidad cero, 0 dependencias externas.
- **Decisión:** **ACEPTAR / RECOMENDADO**. Implementar `.opencode/commands/memory-status.md` y `.opencode/commands/handoff.md`.

### 2. Estándar de Registros de Decisiones de Arquitectura (ADR Nygard/MADR)
- **Fuente/Licencia:** Public Domain / CC0 / MIT (`joelparkerhenderson/architecture-decision-record`).
- **Maturidad:** Estándar industrial maduro.
- **Qué resuelve:** Plantilla Markdown estandarizada para registrar decisiones arquitectónicas (`Número`, `Título`, `Fecha`, `Estado`, `Contexto`, `Decisión`, `Consecuencias`).
- **Integración:** Complejidad cero (plantilla pura en `StorageEngine`).
- **Decisión:** **ACEPTAR / RECOMENDADO**.

### 3. Frameworks de Memoria Vectorial / Daemons Externos (ChromaDB, MemGPT, Claude-Mem)
- **Licencia:** AGPL-3.0 (Claude-Mem), Apache 2.0 (MemGPT), MIT (ChromaDB).
- **Motivo de Descarte:**
  - `claude-mem` es AGPL-3.0 (viola restricción Clean-Room MIT).
  - Vector DBs introducen binarios C++ nativos pesados y huella de memoria innecesaria para un proyecto local sin dependencias.
  - Daemons externos violan el principio de arquitectura integrada en OpenCode.
- **Decisión:** **DESCARTAR / RECHAZADO**.

## D. Arquitectura Propuesta F3.4

1. **StorageEngine como SSOT (`src/storage.ts`):**
   - Incorporar interfaz `ADRRecord`: `{ id: string; title: string; status: string; date: string; context: string; decision: string; consequences?: string }`.
   - Incorporar métodos ADR:
     - `saveADR(...)`: Guarda `ADR-xxx.md` atómicamente en `.openmemory/adrs/`.
     - `listADRs()`: Parsea el directorio `.openmemory/adrs/` y retorna lista indexada.
     - `getADR(id)`: Lee el contenido exacto de un ADR.
   - Incorporar métodos de tareas/metas:
     - `addTask(description)`
     - `updateTaskStatus(id, status)`
     - `setActiveGoal(goal, phase)`
     - `formatProjectContextSummary()`
2. **Comandos Slash Nativos (`.opencode/commands/`):**
   - `.opencode/commands/memory-status.md`: Invocable mediante `/memory-status`.
   - `.opencode/commands/handoff.md`: Invocable mediante `/handoff`.
3. **Integración con Plugin (`.opencode/plugins/openmemory.ts`):**
   - Extender `session.created` para emitir en el log el resumen estructurado generado por `formatProjectContextSummary()`.

## E. Contrato F3.4

- **Inputs:** Títulos de ADR, decisiones, adición/actualización de tareas, cambio de meta activa, eventos de ciclo de vida.
- **Outputs:** Archivos `ADR-xxx.md` en `.openmemory/adrs/`, `project-state.json` actualizado, comandos `.opencode/commands/`, síntesis de contexto.
- **Invariantes:** Escrituras atómicas via `.tmp` + `fs.renameSync`. Sin destrucción de notas humanas ni ADRs existentes.
- **Propiedad:** `StorageEngine` posee la autoridad sobre `.openmemory/adrs/`, `project-state.json`, `openmemory.json`, `handoff.md`.
- **Lifecycle Hooks:** `session.created`, `session.idle`, `session.compacted`.
- **Manejo de Errores:** Recuperación segura ante JSON corruptos o directorios faltantes. Fallback limpio en hooks experimentales.
- **Compatibilidad Hacia Atrás:** 100% compatible con F3.1, F3.2 y F3.3.
