## 3. Technology & OSS Evaluation: Packaging & Distribution

### A. Evaluated Build Alternatives

1. **Option 1: OSS Bundlers (`tsup` / `esbuild` / `rollup`)**
   - *Evaluation:* Bundles all files into single bundle JS files.
   - *Verdict:* **REJECTED.** Adds 10MB+ devDependencies (`tsup`, `esbuild`), introduces opaque binary compilation steps, and risks bundling external runtime dependencies (`@modelcontextprotocol/sdk`, `zod`) rather than declaring them cleanly in `dependencies`.

2. **Option 2: Native TypeScript Compiler (`tsc`) + `package.json` Standard Fields (SELECTED)**
   - *Evaluation:* Standard Node.js library packaging workflow using `tsc` (already in `devDependencies`).
   - *Verdict:* **APPROVED (Reusability Principle).** Zero new dependencies, 100% MIT Clean-Room compliant, generates clean JavaScript (`dist/*.js`) and type declarations (`dist/*.d.ts`) matching source files 1:1, full source map support.
