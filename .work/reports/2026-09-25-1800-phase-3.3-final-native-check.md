## 1. Resolution of `AGENTS.md` File List Inconsistency

* **Auditing Question**: Is modifying `AGENTS.md` strictly necessary?
* **Findings**: **YES**. `AGENTS.md` is OpenCode's official, native entry point for project conventions and system prompt instructions. To ensure OpenCode's LLM agent knows where to locate the cross-session handoff state upon starting a new session, a non-destructive delimited pointer block must be placed in `AGENTS.md`:
  ```markdown
  <!-- OPENMEMORY:START -->
  ## OpenMemory Context Pointer
  Active session handoff state: `.openmemory/handoff.md`
  Active project state: `.openmemory/project-state.json`
  <!-- OPENMEMORY:END -->
  ```
* **Resolution**: `AGENTS.md` is explicitly added to the list of target files modified during installation/setup using non-destructive regex delimiters and timestamped backups in `.openmemory/backups/`.

## 2. Investigation of `experimental.session.compacting` Hook

* **Capability**: OpenCode plugin API exposes `experimental.session.compacting`, which fires *before* context window compaction and accepts `{ context: Array<string>, prompt: string }`.
* **Findings**:
  1. **Execution Point**: Pre-compaction.
  2. **Inputs**: Receives compaction prompt and context array.
  3. **Modifications**: Allows appending `.openmemory/handoff.md` content directly into the compaction prompt.
  4. **LLM Ingestion**: Confirmed. OpenCode appends plugin-provided context to the summarization prompt.
  5. **Summary Storage**: The resulting summary is stored in OpenCode's local SQLite DB (`opencode.db`).
  6. **Failure Resilience**: If the hook throws, OpenCode falls back to default compaction without crashing.
  7. **Status**: Marked `experimental` in OpenCode Plugin API.
  8. **Compatibility Risk**: HIGH risk if OpenCode renames or deprecates the experimental API in future versions.

## 3. Strategy Comparison (Hybrid Dual-Layer Decision)

| Criterion | Strategy A (`session.compacted` Stable Hook) | Strategy B (`experimental.session.compacting`) | Strategy C: Hybrid Dual-Layer (RECOMMENDED) |
| :--- | :--- | :--- | :--- |
| **Stability** | **High (100% Stable API)** | Low (Experimental API) | **High (Stable core with progressive fallback)** |
| **Compaction Ingestion** | Indirect (Disk handoff update) | Direct (Prompt injection) | **Direct with zero failure risk** |
| **Compatibility Risk** | Zero | High | **Zero (Safeguarded via try/catch)** |

**Decision**: Adopt **Strategy C (Hybrid Dual-Layer)**:
* **Core Engine**: Use stable `session.compacted` hook to update `.openmemory/handoff.md` atomically.
* **Progressive Enhancement**: Add optional listener for `experimental.session.compacting` wrapped in a safe `try/catch` fallback so that if OpenCode changes the API, OpenMemory continues working with 100% stability.
