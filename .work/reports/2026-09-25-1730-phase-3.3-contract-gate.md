## 2. Gate 1 — Verification of Real Context Recovery (`session.created`)

* **OBSERVACIÓN**: `StorageEngine.getOrInitHandoff()` se ejecuta en `.opencode/plugins/openmemory.ts:L72` al recibir `session.created`.
* **EVIDENCIA**: El contenido de `handoff.md` se lee del disco (`src/storage.ts#L170`), pero en la versión actual del plugin se utiliza únicamente para calcular `handoffWords: handoffContent.split(/\s+/).length` y registrarlo en `.openmemory/logs/events.jsonl` (`openmemory.ts#L78`).
* **CONCLUSIÓN**: `handoff.md` actualmente se lee y valida, pero **NO se inyecta automáticamente al prompt del agente**.
* **MECANISMO DE INYECCIÓN DE CONTEXTO APORTADO**: Para que el agente lea `handoff.md` automáticamente en OpenCode, se agregará una instrucción de puntero delimitada en `AGENTS.md`:
  ```markdown
  <!-- OPENMEMORY:START -->
  ## Session Continuity Notice
  Always read `.openmemory/handoff.md` for current project goal and pending tasks.
  <!-- OPENMEMORY:END -->
  ```

## 3. Gate 2 — Lifecycle Hook Responsibility Matrix (`session.idle` vs `session.compacted`)

| Lifecycle Event | Event Purpose | Allowed Updates | Strictly Prohibited Overwrites | `session.compacted` Strategy |
| :--- | :--- | :--- | :--- | :--- |
| **`session.created`** | Reconstitute session state | `project-state.json` (`sessionRunCount`, `lastSessionId`, `SESSION_ACTIVE`) | **Prohibited** from overwriting `handoff.md` | N/A |
| **`session.idle`** | Persist turn checkpoint | `project-state.json` (`IDLE_CHECKPOINT_SAVED`, `lastIdleTimestamp`) | **Prohibited** from writing redundant handoff updates | N/A |
| **`session.compacted`** | Update handoff summary pre-context trim | `.openmemory/handoff.md` (Auto sections), `project-state.json` (`COMPACTION_CHECKPOINT_SAVED`) | **Prohibited** from overwriting manual developer sections (`## Key Architectural Decisions`) | **Option D**: Update auto sections, preserve manual sections, dump evidence payload. |

## 4. Gate 3 — Handoff Section Ownership Model (`.openmemory/handoff.md`)

| Section in `handoff.md` | Owner | Auto-Written by Engine | Mandatory Preservation |
| :--- | :--- | :---: | :---: |
| **Header (Active Goal, Phase, Last Updated)** | OpenMemory Engine | **Yes** | No |
| **`## Progress Summary`** | OpenMemory Engine | **Yes** | No |
| **`## Key Architectural Decisions`** | Developer / Human | **No** | **YES (MANDATORY)** |
| **`## Uncommitted Work & Next Steps`** | OpenMemory Engine | **Yes** | No |
| **`## Developer Notes` / Custom Sections** | Developer / Human | **No** | **YES (MANDATORY)** |

**Golden Rule**: `StorageEngine.updateHandoff()` parses Markdown sections by `## ` headers. It replaces only auto-owned sections and concatenates/preserves 100% of human-owned or unknown sections verbatim.

## 5. Gate 4 — `project-state.json` vs `CURRENT.md` SSOT Resolution

1. **Single Source of Truth**: `.openmemory/project-state.json` is the sole machine-readable SSOT for OpenMemory.
2. **Role of `.work/CURRENT.md`**: Bitácora operacional temporal en `.work/`. Serves as active turn documentation for human/agent review, but is NOT read by `StorageEngine`.
3. **Synchronization Policy**: F3.3 synchronizes only `project-state.json` and `handoff.md`. `CURRENT.md` is updated manually at phase/session boundaries.

## 6. Gate 5 — Git Snapshot Assumption Verification

* **Audit Finding**: The previous assertion (*"OpenCode creates automatic git commits on destructive edits"*) is an internal runtime feature of OpenCode tools, NOT a guaranteed interface contract for OpenMemory.
* **Contract Adjustment**: **Affirmation withdrawn**. OpenMemory relies strictly on its own atomic file writer (`atomicWriteFileSync` with `.tmp` + `fs.renameSync`) and timestamped backups in `.openmemory/backups/`.
