## 1. Executive Summary

This report delivers a read-only forensic audit and architectural discovery for **Sub-phase F3.3 (Session Handoff & Continuity Engine)**.

### Primary Architectural Finding
Creating a separate `HandoffEngine` class in `src/handoff.ts` is **UNNECESSARY INFRASTRUCTURE BLOAT**. 

Instead, session handoff continuity can be achieved with **zero extra class abstractions** by:
1. Extending `StorageEngine` (`src/storage.ts`) with structured handoff section management methods (`updateHandoffSection()`, `generateHandoffSummary()`).
2. Connecting handoff updates directly into the existing plugin `.opencode/plugins/openmemory.ts` on `session.compacted` and `session.idle` events.
3. Exposing a native slash command `.opencode/commands/handoff.md` in F3.4 for manual handoff triggers.

This design reuses 100% of the atomic file writer (`atomicWriteFileSync`), maintains single storage authority, preserves 0-dependency local execution, and prevents token overhead.

## 6. Alternativas Investigadas

### Option A: Dedicated `HandoffEngine` Class in `src/handoff.ts`
* **Pattern**: Create a new TypeScript file `src/handoff.ts` containing `export class HandoffEngine`.
* **Pros**: Separate class file for handoff logic.
* **Cons**: Duplicates file write logic, increases import complexity, adds unnecessary class abstraction for a feature that only reads/writes `.openmemory/handoff.md`.

### Option B: Extend `StorageEngine` (`src/storage.ts`) + Plugin Integration (RECOMMENDED)
* **Pattern**: Extend existing `StorageEngine` in `src/storage.ts` with methods `updateHandoff(summary: HandoffSummary): void` and `parseHandoff(): HandoffSummary`. Connect directly in `.opencode/plugins/openmemory.ts`.
* **Pros**: Zero extra class bloat, 100% atomic writer reuse, single storage authority, minimal maintenance overhead.
* **Cons**: Slightly expands `StorageEngine` method count (~30 additional lines).

### Option C: External Daemon / MCP Server for Handoff
* **Pattern**: Run background service or MCP server over STDIO/HTTP to generate handoff state.
* **Pros**: Cross-client standard.
* **Cons**: Violates zero-dependency local plugin principle, adds process management complexity.

## 9. Failure Modes & Resilience Safeguards

| Failure Case | Risk | Expected Behavior | Recovery Safeguard |
| :--- | :--- | :--- | :--- |
| **1. Abrupt Session Crash** | Low-Medium | Incomplete in-memory state lost. | `.openmemory/project-state.json` remains intact on disk via `session.idle` checkpointing. |
| **2. Process Interrupted Mid-Write**| High | Partially written file corrupts state. | Atomic writer (`atomicWriteFileSync`) writes to `.tmp` file first, then executes atomic `fs.renameSync`. |
| **3. Stale `.tmp` Files Left Behind**| Low | Temporary files accumulate in `.openmemory/`. | `StorageEngine` cleans up `.tmp` files older than 24 hours during `ensureStorageStructure()`. |
| **4. Corrupted JSON Syntax** | Medium | `JSON.parse` throws syntax error. | `StorageEngine` catches parse error, logs warning, and auto-initializes clean default state (`F3.1-003`). |
| **5. Missing `.openmemory/` Directory**| Low | Filesystem `ENOENT` error. | `ensureStorageStructure()` recursively creates directory hierarchy (`F3.1-001`). |
| **6. Concurrent Plugin Writes** | Low | Race condition between events. | Synchronous atomic file writes with unique timestamped `.tmp` paths prevent write collisions. |
| **7. Handoff File Exceeds Word Limit**| Medium | Context window token bloat. | `StorageEngine.saveHandoff()` enforces `maxHandoffWords` limit (500 words) by truncating excess log narrative. |

## 12. Recomendación Técnica

**Adoptar la Opción B (Extender `StorageEngine` en `src/storage.ts`)**.

Do **NOT** create `src/handoff.ts` or a separate `HandoffEngine` class. Instead:
1. Add structured handoff helper methods (`updateHandoffSection`, `truncateHandoffWords`) to `StorageEngine` in `src/storage.ts`.
2. Update `.opencode/plugins/openmemory.ts` to invoke `storage.updateHandoffSection()` upon `session.compacted` and `session.idle` events.
3. Defer slash command triggers (`/handoff`) to Sub-phase F3.4.
